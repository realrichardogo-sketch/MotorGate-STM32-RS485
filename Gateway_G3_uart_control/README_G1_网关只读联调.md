# G1 网关只读联调

## 工程来源和目标

以商家 `实现代码.zip/gateway_32_rs485` 的网关板初始化和引脚配置为基础，提取最小的 HAL 程序。此版本不启动原工程的 FreeRTOS、MQTT、以太网、CAN，也不发送任何 Modbus 写命令。只使用 USART2 每约 1 秒查询一次**电机板 M13** 的 10 个输入寄存器，将结果放在可调试的全局变量中，并通过网关 USART1_TX 输出日志。

**仅烧录网关板**；电机板保留已经完成无动力自检的 `PPP03_M13_rs485_readonly`。两个固件不能交叉烧录。请保留网关板的原始固件或工程副本。

## 与商家协议表的区别

商家 `Modbus通信协议4.0.xlsx` 的示例使用从站地址 `05`，按功能码 04 读起始地址 `0002`，还列有控制线圈及写寄存器；其中表格的 3xxxx/4xxxx 标签与功能码标注有交叉。本 G1 **以现有电机板 M13 的实际代码为准**，固定发送 `01 04 00 00 00 0A 70 0D`：从站 `01`，功能码 `04`，起始偏移 `0`，连续读取 `10` 个寄存器，最后两字节为 Modbus CRC（低字节在前）。G1 只接受首寄存器为 `13` 的合法响应，不会调用商家代码中的电机启动命令。

## 观察变量

可在 Keil 的调试 Watch 窗口观察下列全局变量，或者通过网关 UART1_TX 查看 `115200 8N1` 日志。接串口工具前先按网关实物丝印及原理图确认 H1 引脚，串口侧使用 3.3V 电平，工具和网关共地。

| 变量 | 预期 |
| --- | --- |
| `G1_timeouts` | 只有网关供电、电机板未连接时逐次增加 |
| `G1_frames_ok` | RS485 通信成功后递增 |
| `G1_frames_bad` | 收到长度完整但地址、功能码、CRC 或版本不符的帧时增加 |
| `G1_reg[0]` | 电机板 M13 返回的 `13` |
| `G1_reg[1]` | 电机板状态枚举；0 READY，5 NO ENC |
| `G1_reg[9]` | 电机板上电秒数，持续增长 |

日志示例：`G1 OK ok=3 bad=0 timeout=0 ver=13 state=0 sec=8`。没有物理链路时 `G1 TIMEOUT` 是预期现象。网关运行过程中 `G1_frames_ok` 从 0 增长，才表示两板通信链路通过；OLED 显示正常本身不代表 RS485 通信成功。

## 建议验收顺序

1. 网关与电机板的**电机动力电源断开**。打开 `MDK-ARM/gateway_32.uvprojx`，在 Keil 中 Rebuild，确认 `0 Error(s)`；核对新 HEX 的路径/时间，仅烧录之前 ST-LINK 识别为 **128 KB** 的网关板。本包不附带旧 HEX。若编译失败，保存完整日志；不要改用原始商家的 MQTT 网关 HEX。
2. 先只给网关板按此前接法提供逻辑供电；用 Keil Watch 观察 `G1_timeouts` 是否递增（此时超时属正常）。若能确认实物上 H1 的 UART1_TX 与 GND，也可通过 USB 转 TTL **3.3V** 串口查看日志，但不用它连接 RS485 A/B。
3. 两板**全部断电**，确认实物 RS485 端子标识，再仅连接网关 `485A→电机板485A`、`485B→电机板485B`、`GND→GND`。原理图上同一个 CN15 还有 12V 接脚，接线时不要误接电源脚；P2 是调试接口。两块板各用已经验证过的逻辑供电方式。不要接通金属电机动力电源。
4. 重新上电，等待数秒，核对 `G1_frames_ok` 递增、`G1_reg[0] == 13`、`G1_reg[9]` 递增。若只增加 `G1_timeouts`，检查两块板是否确有 RS485 芯片与接线端子、供电、A/B/GND 实物丝印、从站地址和串口设置。不要试发写命令。

网关源工程 Keil 目标条目写 STM32F103C8，G1 同样设在其 64 KB 构建配置内；你此前的 ST-LINK Utility 曾在网关板读出 128 KB，最终仍以网关板实物丝印和 Keil 编译/烧录结果确认。现在是只读链路验证，不能据此推断带负载位置精度或电流保护可用。

## 本地验证

已核对工程内仅有功能码 04 的请求，计算得到 CRC 报文 `01 04 00 00 00 0A 70 0D`，并对改动的 HAL 源做主机 GCC 语法检查。此环境无法执行 Keil ARMCC 或真实板卡通信；上板须遵循以上分阶段验收。
