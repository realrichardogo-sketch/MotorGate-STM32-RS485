# G1 网关 RS485 只读诊断版

适用于电机板 OLED 显示 `M13:READY`、网关 `G1_timeouts` 增加而 `G1_frames_ok` 为 0 的情况。仅修改网关侧：应答等待从 300 ms 延长至 1500 ms，并增加发送结果及实际收到的字节数。请求仍为 `01 04 00 00 00 0A 70 0D`，不含写命令；电机板保持原 M13 固件，不修改、不烧录。

## 为什么测试等待时间

M13 的主循环每轮都通过 100 kHz I²C、以 1048 次两字节事务刷新整个 OLED。仅 27 位时钟/事务的理论下限已接近 283 ms，实际还包括函数及总线开销。若请求抵达时电机板正在刷新，原 G1 的 300 ms 接收窗口可能过短。延长窗口是诊断手段，不代表此原因已经证实。

## 安装与验收

1. 保存当前已烧录的 G1 工程和网关原厂程序备份。解压本包到独立目录，用 Keil 打开 `MDK-ARM/gateway_32.uvprojx` 并 Rebuild，确认 0 Error(s)。仅将**本包重新生成**的 `MDK-ARM/gateway_G1_readonly/gateway_G1_readonly.hex` 烧录网关板。不要向电机板烧录网关固件。
2. 两板沿用已确认的原装六芯排线和既有逻辑供电；保持电机动力电源断开，确认电机板 OLED 为 `M13:READY`。
3. 用 Keil 调试网关，将以下六个变量加入 Watch：`G1_tx_ok`、`G1_tx_errors`、`G1_rx_bytes_last`、`G1_frames_ok`、`G1_frames_bad`、`G1_timeouts`。运行约 10 秒后暂停记录，重复一次。数值默认十六进制。

| 观察结果 | 下一步判断 |
| --- | --- |
| `G1_frames_ok` 递增且 `G1_reg[0]` 为 13 | 只读通信通过，原 300 ms 窗口可能过短；仍需验证更合理的 OLED 刷新与通信调度。 |
| `G1_tx_errors` 递增 | 网关 USART2 发送本身失败；检查 UART 状态和配置。 |
| `G1_tx_ok` 递增、`G1_rx_bytes_last` 一直为 0 | 请求已交给 USART2，但无任何应答字节到达网关 UART；再核查收发器/线序或电机板 Modbus 初始化和接收。此计数不能证明 A/B 线上已实际发送。 |
| `G1_rx_bytes_last` 为 1～24 | 收到部分字节；排查报文时序、串口错误及接收帧长。 |
| `G1_frames_bad` 递增 | 收到完整 25 字节，但地址、功能码、CRC 或版本不合预期。 |

`M13:READY` 是本地 UI 状态，无法单独证明 `m13_modbus_ready` 已成功初始化。若延长等待仍收不到任何字节，下一步用 ST-LINK 调试电机板，观察该变量及接收缓冲区。

本包的改动文件经主机 GCC 语法检查；仍须以 Keil 编译和板上测试为准。
